四、我踩过的坑

以下所有问题均为我搭建过程中亲身遇到、逐一排查解决的真实报错。

1. 环境安装成功，终端依然提示命令不存在

问题原因：软件安装时未勾选自动配置环境变量，或手动配置路径错误，系统无法识别 hexo、node 等命令。

解决方案：重新安装 Node.js 和 Git，务必勾选自动配置环境变量；若已安装，手动找到软件安装路径，添加到系统环境变量后，重启终端再测试。

2. hexo s 启动失败，终端报错、页面无法访问

问题原因：博客文件夹依赖缺失、npm 缓存冲突、初始化文件残缺。

解决方案：依次执行清理、重装依赖、重启服务命令：

3. 更换 Butterfly 主题后，网站样式错乱、纯白空白

问题原因：99% 是未安装主题专属渲染依赖，这是新手最容易遗漏的步骤，默认主题无需这些依赖，Butterfly 必须单独安装。

解决方案：执行上文的 pug、stylus 渲染依赖安装命令，清理缓存后重启服务即可恢复正常样式。

4. 配置文件修改后不生效，改了白改

问题原因：两个核心误区：一是混淆全局配置和主题配置文件，二是修改配置后未清理缓存、未重启服务。

核心区分：

  • 根目录 _config.yml：全局配置（网站标题、描述、部署仓库）
  • themes/butterfly/_config.yml：主题配置（侧边栏、图标、美化样式）

解决方案：修改任意配置后，固定执行 hexo clean && hexo s，确保新配置生效。

5. Markdown 文章无法渲染、图片不显示

问题原因：文章命名不规范、图片路径错误、特殊符号冲突。

解决方案：文章文件名尽量只用英文、数字、下划线，避免中文和空格；图片使用正确路径，存放到规范文件夹，避免路径识别失败。

6. 部署 GitHub Pages 失败，网页加载空白

这个放到 GitHub 部署部分详细讲解。

5. 生成静态文件 + 一键部署（每次更新博客都要执行这三步）

在博客根目录终端依次执行：

  • 部署到个人主页：https://你的用户名.github.io
  • 部署到项目页：https://你的用户名.github.io/你的仓库名/

我在 GitHub Pages 部署时踩过的坑

1. 仓库名字写错，网站打不开

  • 部署到个人主页时，仓库名必须是 用户名.github.io，大小写严格匹配
  • 部署到项目页时，仓库名可自定义，但访问路径要带上仓库名

2. hexo d 报错，提示权限不足

  1. 确认 repo 地址是否正确，是否多复制了空格
  2. SSH 方式：确认已生成 SSH 密钥并添加到 GitHub 账号
  3. HTTPS 方式：使用 Personal Access Token 代替账号密码登录

3. 部署成功，但打开网页 404

  1. 查仓库发布分支是不是 main
  2. 项目页还要检查 url 和 root 是否和仓库名一致
  3. 等待几分钟再刷新
  4. 确认 hexo g 生成了 public 文件夹

4. 每次更新文章，网页不变

每次写完文章，必须执行 hexo clean && hexo g && hexo d，清理缓存再重新生成 + 部署

搭建复盘

这次从零搭建 Hexo 博客，看似是简单的工具部署，实则让我收获很多。所有报错和 bug，基本都源于细节遗漏、配置混淆、文件存放不规范，而非操作难度过高。

踩坑的过程，也是快速学习、积累经验的过程，不仅熟练掌握了 Hexo 博客的搭建、配置、排错方法，也对前端静态网站、Git 部署、环境配置有了更清晰的认知。
